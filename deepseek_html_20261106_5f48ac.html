Projeto de Portfólio · Ciência de Dados

Comportamento do Consumo Musical

Um projeto de ciência de dados que investiga como as pessoas consomem música, o que torna uma faixa popular e como características sonoras podem alimentar um sistema de recomendação.

01

Visão Geral

A pergunta central: o que faz uma música ser popular — e como o gosto musical evolui ao longo do tempo, entre gêneros e entre diferentes perfis de ouvintes?

O projeto combina análise exploratória, séries temporais, clustering, testes estatísticos e um sistema de recomendação content-based para transformar dados culturais em insights sobre comportamento do consumidor.

🎯

Objetivo

Investigar tendências de consumo musical e as características associadas à popularidade.

🧪

Diferencial

Testar hipóteses estatísticas em vez de apenas descrever os dados.

🚀

Entregável final

Dashboard interativo + recomendador content-based + relatório de insights.

02

Hipóteses Testáveis

Transforme perguntas em hipóteses com critério de teste. O resultado (confirmar ou refutar) é sempre um insight válido — e mostra rigor científico no portfólio.

Músicas com maior danceability e menor duração têm popularidade média significativamente maior, controlando por gênero e ano de lançamento.

Teste: regressão múltipla + Mann-Whitney (popularidade não é normal).

O consumo de gêneros com valence alta (músicas "alegres") aumenta nos meses de verão no hemisfério sul.

Teste: decomposição STL + correlação com sazonalidade.

Um recomendador content-based (similaridade sobre audio features) oferece maior diversidade de gênero que um recomendador baseado apenas em popularidade, mantendo relevância.

Teste: comparação de métricas (diversidade, novelty, hit rate).

O clustering de artistas por audio features reproduz os gêneros declarados nas plataformas, ou revela agrupamentos cross-genre?

Teste: Rand Index + matriz de confusão entre clusters e rótulos.

04

Roadmap do Projeto

Fase 1 · Entendimento e Preparação

Base
  • Coleta e integração das fontes de dados
  • Dicionário de dados documentado
  • Limpeza: nulos, duplicatas, outliers
  • EDA inicial: distribuições, correlações, visualizações

Fase 2 · Análise de Tendências

Tempo
  • Séries temporais: evolução de gêneros por década
  • Testes estatísticos de H1 e H2
  • Decomposição sazonal (STL) para H2
  • Visualizações de tendência com Plotly

Fase 3 · Agrupamento e Similaridade

Cluster
  • Normalização das audio features (RobustScaler)
  • K-Means com elbow/silhouette + DBSCAN para outliers
  • Redução de dimensionalidade (PCA ou UMAP) para visualização
  • Matriz de similaridade entre artistas

Fase 4 · Sistema de Recomendação

Modelo
  • Content-based: similaridade de cosseno sobre features normalizadas
  • Híbrido (opcional): combinar similaridade + popularidade
  • Avaliação: diversidade, novelty, hit rate

Fase 5 · Comunicação e Portfólio

Entrega
  • Dashboard interativo em Streamlit
  • Relatório com insights e limitações
  • README narrativo no GitHub
  • Deploy no Streamlit Cloud ou Hugging Face Spaces

07

Armadilhas a Evitar

Popularidade é métrica da plataforma

O campo popularity do Spotify é um score interno (0–100) de streams recentes, não vendas nem relevância cultural.

documentar limitação e, se possível, cruzar com Billboard Hot 100 como segunda medida.

Viés de sobrevivência

Datasets só contêm músicas que "sobreviveram" — as que ninguém ouviu não aparecem.

reconhecer isso ao interpretar tendências históricas.

Audio features são estimativas algorítmicas

Danceability, energy etc. são modelos do Spotify, não rótulos humanos.

mencionar na metodologia e evitar conclusões causais.

Confundimento por fama do artista

Uma música popular pode ser popular por causa do artista, não das features.

controlar por popularidade do artista ou por gênero nos testes.

Correlação ≠ causalidade

Mesmo com H1 confirmada, "músicas curtas causam popularidade" é afirmação causal indevida.

usar linguagem de associação: "há associação estatística entre…".
